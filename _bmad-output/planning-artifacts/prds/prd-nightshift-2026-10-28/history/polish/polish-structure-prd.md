# Structure review: Nightshift PRD

Reviewed 2026-10-31. Lens: structure (bmad-review). This is an AI review: Amine decides row by row. Content is not challenged; only organisation and expression.

**Read of purpose:** this document exists to help Orvex's judge (Danny) assess what Nightshift must do and why, and to give the downstream UX and architecture work a stable, citable set of requirements (FR, PRIV, SEC, COST, NFR, SM IDs) to build on.

**Structure model:** Strategic/Context (Pyramid): top-down, most critical first, logically grouped, MECE. For the ID-numbered requirement blocks, the Reference/Database rule (consistent schema, predictable order) also applies, because downstream readers jump to items by ID.

**Inputs:** `prd.md`, 11,707 words (word_metrics.py). Largest blocks: Glossary 1,774 (15%), Section 3 Features about 5,600, Section 6 Users and journeys 743, Section 8 Success metrics 647, FR-19 478 (the largest single FR). Reader type: humans. Style: Microsoft Writing Style Guide, with the author's standing directives (British spelling, no serial comma, source tags stay, italic status notes may be flagged).

## Summary

- **Recommendations:** 28 rows: 23 changes (CUT, MERGE, MOVE, CONDENSE or QUESTION) and 5 PRESERVE.
- **Estimated reduction if all are accepted:** about 790 words cut, about 60 added (section map), net about 730 words, about 6% of 11,707. The biggest gains: Glossary condensing (about 300), status notes (about 270), FR-19 split (about 70). No length target was given.
- **Highest-leverage changes:** one renumbering pass (FR, PRIV, COST and optionally UJ, plus section order) done together, so cross-references are updated once; Glossary reduced to definitions in dependency order; the stale 9.1 code-fix bullet.
- **Comprehension trade-offs:** none of the cuts removes an example, a source tag or a non-goal. Moving Users and Scope ahead of the Glossary means a few terms (for example "risky repair" in UJ-1) appear before their definition; the journeys already explain them in context. Cutting the status notes removes per-section dates; the memlog keeps them, and the inline tags keep the per-statement sources.
