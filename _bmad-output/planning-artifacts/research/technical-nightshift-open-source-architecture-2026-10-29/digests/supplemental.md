# Supplemental OSS shortlist

Accessed **2026-10-29 UTC**. Official upstream pages only; five grouped web calls. Release lists and security pages are mutable observations, not a complete vulnerability audit. Resource estimates and product fit below are explicitly unmeasured engineering hypotheses. No 10,000-cluster production claim was verified.

## Security evidence and boundaries

Grafana and Tempo publish reporting procedures and historical advisories: [Grafana security](https://github.com/grafana/grafana/security), [Tempo security](https://github.com/grafana/tempo/security). Jaeger states community support is for the latest minor and prioritizes security fixes: [policy](https://github.com/jaegertracing/jaeger/security). Falco's policy distinguishes security vulnerabilities from rule-coverage gaps and some crashes, so advisory counts cannot measure detection completeness: [policy/advisories](https://github.com/falcosecurity/falco/security).

Tetragon's security page lists **GHSA-8cw4-v8rm-5m8m**, published 2026-10-20, concerning unredacted process environment information. Affected/fixed versions were not inspected; do not infer v1.7.1 is cleared. [Security page](https://github.com/cilium/tetragon/security). Chaos Mesh documents security updates for two recent minor versions; its page showed no published advisories, which is not proof of no vulnerabilities. [Policy](https://github.com/chaos-mesh/chaos-mesh/security). Chaos Toolkit's retrieved GitHub security page reports no detected SECURITY.md; its cache was three months old, so present policy status is **not conclusively verified**. [Retrieved page](https://github.com/chaostoolkit/chaostoolkit/security).

**Proposed safeguards:** validate Linux kernel/BTF, driver, capabilities, host mounts and managed-node restrictions for Falco/Tetragon before enabling them; no Fargate compatibility is established here. Kernel sensors and injection daemons deserve explicit threat modeling. Runtime events may contain arguments, file paths and environment secrets; trace attributes can contain tenant identifiers or payloads. Apply local allowlists/redaction before export and retain raw security/trace data inside the approved customer boundary. Keep chaos experiments outside autonomous production remediation until blast radius, credentials, stop conditions and recovery are proven.

## External watchdog comparison

**Healthchecks (BSD-3-Clause)** emphasizes missed scheduled pings, with dashboard/API and notification integrations; upstream release v5.0.3 was observed in this run's observability research. It fits outbound heartbeat monitoring without inbound access to clusters. [Source](https://github.com/healthchecks/healthchecks), [releases](https://github.com/healthchecks/healthchecks/releases).

**Uptime Kuma (MIT)** supports HTTP/TCP/DNS/ping and push monitors plus status pages; release list shows 2.5.8 and 2.5.7. README excludes NFS storage. It fits combined external reachability and heartbeat monitoring. [Source](https://github.com/louislam/uptime-kuma), [releases](https://github.com/louislam/uptime-kuma/releases). Its security page lists recent privilege-escalation and badge-endpoint DoS advisories; fixed-version applicability remains unchecked. [Policy/advisories](https://github.com/louislam/uptime-kuma/security).

Either watchdog must run outside the monitored cluster/account failure domain and receive minimal opaque identifiers. Monitor it independently; missing heartbeats cannot distinguish partition from failure. Neither candidate's 10,000-monitor capacity or HA behavior was verified.

**Unmeasured planning placeholders:** reserve approximately 0.25–1 CPU and 256 MiB–1 GiB RAM for an initial single-process dashboard/watchdog trial; these are test starting points, not vendor requirements or production sizing. Trace backends, kernel sensors and chaos workloads need workload-specific measurements; no credible shared numeric envelope was established. Record p95 resource use, event loss, retention cost and disconnected operation before fleet multiplication.
